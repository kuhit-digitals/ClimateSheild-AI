# ClimateShield AI — Full-stack prototype

This package extends the existing ClimateShield HTML/CSS/vanilla JavaScript dashboard rather than replacing it with a new frontend. It adds a Python FastAPI backend and a local SQLite database.

## Features implemented

- Existing overview, charts, business directory, search, filters, and business detail drawer retained.
- Business and alert records load from the local API and persist in SQLite.
- Add a business and calculate its risk score through the backend.
- Risk simulator that submits inputs to the backend and returns an explainable scenario score.
- Alert status changes (`Open`, `Monitoring`, `Resolved`) saved to SQLite.
- Portfolio summary and CSV export generated by the backend; browser print can be used to save the report as PDF.
- Basic local display preferences.
- API endpoints for health, businesses, assessments, alerts, summary, risk distribution, climate exposure, simulations, and portfolio reports.
- The original sample records seed the database on first launch.

## Important data note

The business names and exposure values in this prototype are illustrative seed data. The score is a rule-based calculation:

`score = round(0.40 × financial vulnerability + 0.60 × average available climate exposure)`

Risk bands are Low (0–29), Moderate (30–49), Elevated (50–69), and High (70–100). This is not a scientifically validated risk model. No live weather or climate provider is connected yet; the API labels climate data as illustrative.

## Run on Windows

1. Extract this folder to a location you can edit.
2. Install Python 3.10 or newer if it is not installed.
3. Double-click `run_windows.bat`.
4. The first run creates `.venv`, installs dependencies, and starts the local server. Keep the terminal open.
5. Open **http://127.0.0.1:8000** in your browser.
6. Open **http://127.0.0.1:8000/docs** to inspect and try the API endpoints.

The frontend and backend are served by the same local process, so you do not need a second terminal or a separate database server. The database file is created at `backend/climateshield.db` on first run and is ignored by Git.

## Useful API endpoints

- `GET /api/health`
- `GET /api/businesses`
- `POST /api/businesses`
- `GET /api/assessments`
- `GET /api/businesses/{business_id}/assessments`
- `GET /api/alerts`
- `PATCH /api/alerts/{alert_id}`
- `GET /api/dashboard/summary`
- `GET /api/dashboard/risk-distribution`
- `GET /api/climate/exposure`
- `POST /api/simulations`
- `GET /api/reports/portfolio`
- `GET /api/reports/portfolio.csv`

## Troubleshooting

- If `py` is not recognized, install Python and enable the Python launcher, or replace `py` with `python` in `run_windows.bat`.
- If the server says port 8000 is busy, stop the other server using that port before retrying.
- Do not open `index.html` by double-clicking it for full functionality; start the backend and open the local URL above.
- Keep the `.venv` and `backend/climateshield.db` files out of Git commits.
